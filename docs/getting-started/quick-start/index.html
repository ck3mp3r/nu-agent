Quick Start

Build and install

nu-agent is a Nushell plugin, so it ships as a separate binary. Build it in release mode and register it with Nushell:

cargo build --release
plugin add target/release/nu_plugin_agent
plugin use agent

plugin add records the binary path in Nushell's plugin registry, and plugin use loads it. The command name is agent: the nu_plugin_ prefix is what makes the binary a plugin.

Configure a model

Generate a starter config from your environment:

agent config init          # creates config.toml (errors if it already exists)
agent config init --force  # overwrite an existing config.toml

agent config init scans for OPENAI_API_KEY / ANTHROPIC_API_KEY and any AGENT_* overrides, and writes a config.toml reflecting them. The file lives at {config base}/nu-agent/config.toml — ~/.config/nu-agent/config.toml by default; a debug build reads nu-agent-dev/ instead.

Then edit the file and set a model. Two blocks are enough to run against a local Ollama server:

[models.default]
model = "ollama/gemma4:31b"

[providers.ollama]
base_url = "http://127.0.0.1:11434"

First run

Pipe a prompt into the agent:

"explain this repo" | agent

The input can be a plain string, or a record with prompt and an optional context:

{ prompt: "Summarize", context: "short bullets" } | agent

Common flags

# Override the model for one call
"quick answer" | agent --model "ollama/gemma4:31b"

# Quiet mode (suppress non-essential progress UX)
"debug this" | agent --quiet

# Progressive verbosity on the stderr UX
"debug this" | agent -v
"debug this" | agent -vv
"debug this" | agent -vvv

# Load a persona for instructions and configuration
"implement the feature" | agent --agent coder
